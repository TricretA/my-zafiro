# Agent browser: build notes (feat/browser)

Status: implemented, compiled and unit-tested by CI only. **UNVERIFIED on a phone.**

## What exists
- `app/.../app/browser/`: `WebBrowserScreen` (implements `BrowserScreen`), `WebBrowserSession` (implements `BrowserSession`, one `TabManager` per screen),
  `WebBrowserHost` (owns all WebViews and their surface), `WebSnapshotParser`/`WebYaml` (pure parsing), `BrowserTabs.kt` (`TabManager`, `WebUrls`), `BrowserPrefs`.
- `app/src/main/assets/browser/zbrowser.js`: injected into every page. `snapshot()` walks the DOM (shadow roots, same-origin iframes), keeps visible,
  in-viewport, un-occluded interactive and readable elements (max 300, 600 ms budget), returns JSON; `tap/longTap/tapAt/setText/scrollNode/scrollAt/key` act on the
  element list of the LAST snapshot. `node --check` passes in the sandbox; it has not run in a WebView.
- Screens: `screens open kind=browser` creates `web-N` (one per conversation, same owner scoping as virtual displays; a browser opened from the app has no owner and
  is visible to every agent). `open` with `uri` loads a URL; `screenshot` draws the WebView to a PNG. `screens close`, `list` work.
- Node format: same `NodeInfo`/`ScreenCompact` text, tokens `{version}_{index}` and bare numbers unchanged. Bounds are device pixels (css px x WebView width / viewport width).
- `ScreenCompact` prints extra `url:` and `page:` lines (title, scroll position, "more below") when the snapshot has a URL; phone output is unchanged.
- UI: History menu tile "Browser" -> "Agent browser" settings (global switch default ON, desktop site, where it renders, tab list, clear cookies and data) -> "Browser" page
  (address bar, back/forward/reload/new/close tab, live WebView). Strings in `autonomy_strings.xml`.
- Skill `agent-browser` (generated by `tools/autonomous/gen_workspaces.py`; starts OFF, workspaces turn it on). Researcher agents now also get `screens`, `screen_operation`, `open`.

## Deviations
- `SemanticType` gained `LINK` and `HEADING` (compact codes `link`, `h`); the only exhaustive `when` over it was `ScreenCompact`.
- Per-agent access is prompt-level only (skill lists), as agreed. The global switch is enforced in code.
- Popups are not supported: `setSupportMultipleWindows(false)`, so `target=_blank` loads in the same tab.
- File chooser, downloads, permission prompts, geolocation, `confirm()`/`prompt()` (declined) are blocked or auto-handled; the last event is shown once as a `dialog:` line in `format:"full"`.
- Cookies are app-wide (all WebViews of Zafiro share one jar), separate from Chrome. No per-agent profiles.
- Default WebView user agent is kept (honest): no spoofing to get past Google or Cloudflare.

## Hosting limits (read before trusting unattended runs)
1. Owner has the Browser page open: the WebView container lives in the page.
2. Otherwise, if "Display over other apps" is granted: a full-screen, 1 percent alpha, untouchable overlay window hosts it. This is the intended unattended path. Not verified: whether
   Tecno/HiOS or Android 12 throttles rendering of an almost transparent window, and whether `View.draw` screenshots are non-blank there.
3. Otherwise: no window; the container is measured by hand. Loading, JS and snapshots should work; screenshots and some pages may not. The settings page says which mode is active.
Memory: at most 3 tabs per screen and 4 WebViews in the app (`TAB_LIMIT`/`BROWSER_LIMIT`). A crashed render process revives the tab on next use.

## Known gaps
- Cross-origin iframes are not read. `select` cannot be tapped open; use `set_text` with the option text. Canvas pages need `screenshot`.
- No in-page text search beyond the 300 visible nodes; scroll to see more.
- Sign-in with Google is blocked by Google in embedded WebViews; Cloudflare challenges may appear. Use Chrome on the phone screen.
