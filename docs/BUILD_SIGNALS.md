# Realtime signals (feat/signals)

Status: built, covered by JVM unit tests and CI. **UNVERIFIED on a phone**: nobody has granted notification access and watched a real notification arrive.

## Why
Zafiro only learned about the world when a scheduled task polled. The owner asked how it would know that someone commented on a Substack post, or that the owner texted it back on WhatsApp. A notification listener turns those phone notifications into signals that agents read.

## Pieces
| Piece | Where |
|---|---|
| Pure logic (classifier, command grammar, store, throttle, untrusted fencing, tiny JSON) | `autonomy/core/.../core/signals/` (JUnit, no Android) |
| `SignalsTool` (the `signals` tool), `SignalWatchdog` | `autonomy/android/.../signals/` |
| `SignalListenerService`, `SignalPipeline`, `OwnerCommandRunner`, `SignalConfigStore` | `app/.../zafiro/signals/` |
| Settings page "Realtime signals" (General settings row) | `SignalsSettingsContent.kt`, `SignalsPage` |
| Tool `signals` | `SignalsBuiltin` (agent-runtime), group `android_native` |
| Skill `realtime-signals` | generated by `tools/autonomous/gen_workspaces.py` |

Data: `filesDir/signals/signals.jsonl` (capped at 2000 entries / 2 MB, oldest dropped) and `filesDir/signals/config.json` (enabled, allowed_packages, owner_sender_names, optional engagement_keywords). Settings are a plain JSON file, not the XRepo store: the store needs an IPC descriptor per key for one small list and nothing else reads it.

## Flow
notification -> listener (skips own app, group summaries, ongoing; only allow-listed packages) -> `SignalClassifier` -> `SignalStore.add` (dedupe) -> reaction:
* OWNER_MESSAGE: `OwnerCommandParser` -> `OwnerCommandRunner`; the signal is acked.
* ENGAGEMENT / EMAIL: one board item per platform per 10 minutes (counts merged, up to 6 fenced samples) for the department that owns the platform, only if that workspace is ON and installed. Owner of the item = that team's director. Created through `TeamService.run("board", add)`; merging uses `amendTodoBoardItem` (only while the item is still TODO).
* OTHER: stored only.

## Classification
* OWNER_MESSAGE: package is WhatsApp, WhatsApp Business or Telegram, not a group chat, and the sender equals a configured owner name (exact, case/space-insensitive, a leading "~" ignored) or has the same digits as a configured phone number (last 9 digits compared). Substring matching is deliberately not used.
* EMAIL: Gmail. ENGAGEMENT: keyword table (`SignalClassifier.DEFAULT_ENGAGEMENT_KEYWORDS`, whole-word match; replaceable through `engagement_keywords` in config.json) on non-chat apps. Chat apps (WhatsApp, Telegram, Discord, Snapchat) from other people are OTHER, because chat text would trip keywords like "reply".
* Platforms without a department (Telegram, Discord, Twitch, Snapchat, Metricool) are stored but get no board item.

## Owner commands (fixed grammar)
`STATUS`, `PAUSE <dept>`, `RESUME <dept>`, `PRIORITY <text>`, `STOP` / `STOP ALL` / `PAUSE ALL`, `YES <code>`, `NO <code>`; anything else is free text. A command with a missing argument is free text, never guessed. Effects:
* STATUS, PRIORITY, free text: board item "[HIGH] Owner: ..." created by `owner` in the department the text names, else the WhatsApp workspace, else the first workspace that is on; that team's `heartbeat` task is queued immediately (`enqueueManual` + reconcile), the same path as the dashboard "Run now". "High priority" is the `[HIGH]` title prefix (the board has no priority column; adding one needs a Room migration).
* PAUSE / RESUME: `WorkspaceManager.setEnabled` (same code as the Teams page), then an owner board item so an agent confirms by WhatsApp.
* STOP ALL: pauses every enabled workspace and posts a phone notification ("Zafiro paused everything"). It does not cancel a run that is already executing.
* YES / NO `<code>`: the code is the engage action number (`engage op=pending` shows it); it calls `engage approve|reject`. There is no 10-minute expiry in code yet.
* Replies are never sent by the listener. The `realtime-signals` skill tells agents to reply with the WhatsApp recipe.

## Security notes (read these)
* The owner match trusts the name or number WhatsApp shows. A saved contact name cannot be forged by a stranger, but an unsaved sender shows their own number or profile name. Configure the **phone number** as well as the name, and keep the owner as a saved contact.
* Anyone who can make WhatsApp show the configured name can issue commands. If you leave `owner_sender_names` empty nobody can.
* All third-party text is fenced as `<untrusted-XXXXXXXX>...</untrusted-XXXXXXXX>` with a boundary that is random per call; angle brackets and control characters inside are neutralised, so text cannot close the fence. Tool output also carries a standing notice. The settings page shows it as plain text.
* Owner free text is passed to agents as the owner's instruction. That is the point of the channel, and also its risk.

## Resilience
`SignalWatchdog.check` calls `NotificationListenerService.requestRebind` when access is granted but the listener is not connected. It runs at app start, when a scheduled run starts (every heartbeat), when the listener reports a disconnect, and from the settings button. Realtime is best-effort: HiOS and One UI can kill the listener, and scheduled polling remains the fallback. Agents are told to run `signals op=unacked` at the start of every run, so anything captured while they were off is still seen.

## Not done / UNVERIFIED
* Not tried on any phone, including the Tecno BF7. Notification text formats (WhatsApp MessagingStyle, Substack, Instagram) are assumptions from Android docs.
* No "grant through Shizuku" button: `cmd notification allow_listener` would go through the permission layer and `PermissionEntryGuardTest`; left out.
* No new-signal trigger for ENGAGEMENT beyond the board item: a team sees it at its next heartbeat (every 30 minutes), not instantly. Only owner messages start a heartbeat at once.
* The keyword table is English only. Engagement keyword and owner lists are editable in the page; keywords only through config.json.
